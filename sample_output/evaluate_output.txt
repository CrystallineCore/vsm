== 1. Memory is revised, not just added to ===========================
  Session 0: the user tells the assistant some facts.
  Session 1: the user changes their mind.
  
  Q: "Which programming language is my favourite?"
      layered (this project)   -> Rust
      naive RAG                -> C
      mutable + soft delete    -> Rust
  ✓ naive RAG finds the right concept but returns the STALE version (C)
  ✓ layered store returns the current version (Rust)
  ✓ mutable store is also correct at HEAD...

== 2. ...but only the layered store remembers how it got here ========
  history('user::lang'):
      stage 0: C     "My favourite programming language is C."
      stage 1: Rust  "These days my favourite programming language is Rust."
  ✓ time travel: as_of=0 answers 'C' (what we believed after session 0)
  ✓ mutable store cannot: NotSupported('mutable store overwrote history')

== 3. Undoing a poisoned memory without losing later good ones =======
  Session 2: an untrusted web page injects a false 'fact'.
  Session 3: the user genuinely switches editor.
  ✓ memory is now poisoned (Atlantis)
    [stage    ] stage 0      user::lang=C, user::city=Chennai, user::editor=Vim, user::ph  <- session 0
    [stage    ] stage 1      user::lang=Rust  <- session 1
    [stage    ] stage 2      user::city=Atlantis  <- from untrusted web page
    [stage    ] stage 3      user::editor=Helix  <- session 3
  
  Option A, global rollback(2), tried on a free O(#layers) snapshot:
      city=Chennai, editor=Vim
  ✓ global rollback also throws away the good Helix update
  
  Option B, selective revert(stage 2), like `git revert`:
      wrote compensating stage 4; conflicts=[]
  ✓ revert removed Atlantis and kept Helix
  ✓ the poisoned write is still in the audit trail, not silently rewritten

== 4. Delete (reversible) vs forget (physical erasure) ===============
  ✓ after delete(): the phone number is hidden from queries
  ✓ ...but its bytes are still stored, so the delete is undoable
  ✓ rollback(1) on a snapshot undoes the delete
  ✓ mutable soft-delete also still holds the bytes, and cannot undo either
  ✓ naive RAG still RETURNS the deleted phone number
  
  User: 'Forget my phone number. Really.'
      erasure log entry (hash only, no content): {'concept_sha256': '46d4b389b8bcf014', 'at_stage': 5, 'layers_rewritten': 2, 'unix_time': 1790268783.003}
  ✓ after forget(): the number is physically absent from every stored byte
  ✓ rollback past the delete does NOT resurrect forgotten data
